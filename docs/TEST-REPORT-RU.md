# Отчёт о интеграционном тестировании (23.11.2026)

[English version](TEST-REPORT.md)

## Окружение

Реального железа не было, поэтому тесты шли на **настоящей QEMU-эмуляции платы
Cudy WR3000S v1**, а не на имитации парсера конфига:

| | |
|---|---|
| Эмулятор | `github.com/stavultras/router-emulator` v4.1, машина `mt7981-router` |
| Источник | тема 4pda 1087457, пост #10376; папка прошивки `nand-wr3000s` из архива на Яндекс.Диске по той же ссылке |
| Гость | OpenWrt 25.12.5, ядро 6.12.94, aarch64, 256 МБ RAM, overlay 84,8 МБ |
| Хост | aarch64, mihomo Meta v1.19.33 (та же версия, что и цель проекта) |
| Тестовая подписка | локальный HTTP-сервер с пятью нодами: две зарубежные, одна российская, одна LTE, одна инфо-нода «Traffic remaining» |

Официальный веб-эмулятор Cudy (`support.cudy.com/emulator/WR3000S`) проверен
и отвергнут: он только симулирует веб-интерфейс стоковой прошивки и не может
запустить OpenWrt, OpenClash или mihomo.

Чтобы запустить headless на этом хосте, пришлось обойти поставляемый
загрузчик эмулятора (он не мог привязать Unix-сокет монитора QEMU); сама
машина загрузилась нормально.

## Исправления

* `scripts/deploy.sh`: `-p` для `ssh`, `-P` для `scp`; `do_scp()` сначала
  пробует `-O` и откатывается к обычному `scp` для старых клиентов.
* `scripts/build-ruleset.sh`: подсчёт байтов через POSIX `wc -c`.
* `scripts/check-groups.sh`: отвергает любой ответ без `"proxies"`; fallback
  `uclient-fetch` использует `-O` и передаёт Bearer-токен.
* `scripts/apply-rulesets.sh`: поиск процесса берёт первую командную строку,
  где есть `-f ` **и** файл по этому пути существует — скрипт больше не может
  найти сам себя (в его пути есть «openclash»).
* `scripts/build-ruleset.sh`: загрузчик выбирается в рантайме — `curl`,
  `uclient-fetch` (busybox) или `wget`.
* `tests/`: новый регрессионный набор, подключённый к
  `.github/workflows/validate.yml` (и его копии в `automation/`), чтобы CI
  запускал его на каждом PR.
* Доки: EN/RU-версии installation/design/README обновлены; в устранение
  типичных проблем добавлены все новые находки; в `AGENTS.md` — правила 13-15
  и команды запуска тестов.

## Установщик одной командой

`scripts/install.sh` добавлен потому, что гайд описывал каждый шаг, но не было
одной команды, которая их выполняет. Скрипт работает на роутере под POSIX
`sh`: скачивает конфиг, файл перезаписи, четыре скрипта, свой список доменов и
все 28 `.mrs` во временный каталог, подставляет URL и пароль, а затем ставит
всё в раскладку OpenClash. Он сохраняет пользовательский список доменов,
копирует изменённый конфиг в `.bak`, никогда не печатает учётные данные и не
меняет текущую конфигурацию, если какая-то загрузка не удалась.

Дополнительно проверена работа без прав root с нестандартным `ROOT`.

Проверено дважды: `tests/07_install.sh` с локальным HTTP-сервером (35 проверок,
включая `|`, `&` и `\` в учётных данных и все три варианта) и на живом
эмуляторе с `BASE_URL`, указывающим на хост. Прогон на роутере поставил все 28
rule-set'ов, записал `secret: testpass` и URL подписки без искажений, пометил
скрипты исполняемыми и пропустил `mihomo -t`, потому что в тестовом каталоге
ядра не было.

## Схема mixomo

Вторая раскладка этого репозитория отправляет через ядро **только
выбранное**: MagiTrickle отвечает на DNS, помечает адреса из своих списков,
и в ядро идёт только помеченный трафик (через tun-устройство
hev-socks5-tunnel). Всё остальное идёт к провайдеру на полной скорости
линии.

Схема не наша - это
[Internet-Helper/mixomo-openwrt](https://github.com/Internet-Helper/mixomo-openwrt)
с MagiTrickle. Сделано здесь конфигурация под неё: конфиг ядра, состояние
MagiTrickle и скрипты, которые всё это ставят на роутер.

### Что говорят исходники проектов (проверено, не выдумано)

| Факт | Откуда |
|---|---|
| `mixed-port` должен быть 7890; установщик сохраняет конфиг с этим портом и перезаписывает конфиг без него | `src/components/mihomo/install.sh` в mixomo |
| rule-set'ы лежат в `/etc/mihomo/rule-files`, провайдеры - в `/etc/mihomo/proxy-providers` | `src/lib/paths.sh`, `src/runtime/ucode/install.sh` |
| туннель - `hev-socks5-tunnel`, tun-устройство называется `Mihomo`, socks5-порт 7890 | `src/components/hev/install.sh` |
| DNS ядра слушает `0.0.0.0:7880` | `src/assets/config/mihomo.yaml` |
| состояние MagiTrickle - `/etc/magitrickle/state/config.yaml`, у групп интерфейс `Mihomo` или `TPROXY`, состоянию нужен `configVersion` | `src/components/magitrickle/install.sh`, `src/assets/magitrickle/groups-*.yaml` |
| группа с интерфейсом `blackhole` роняет трафик на роутере, без ядра | `src/backend/utils/netfilterTools/ipset-to-link.go` |
| доменное правило MagiTrickle покрывает домен и поддомены; подписка - простой список доменов или CIDR | `src/backend/subscriptions/parse.go` |
| веб-интерфейс экспортирует и импортирует группы в формате `.mtrickle` (JSON) | `src/frontend/src/modules/groups/GroupsView.svelte` |

### Решения, которые навязали исходники

1. **`mixed-port: 7890`, а не 7893.** Не прихоть: установщик mixomo
   сохраняет конфиг роутера только если там этот порт, иначе заменяет его
   дефолтным.
2. **`enhanced-mode: redir-host`, а не fake-ip.** При fake-ip клиент получает
   адрес из 198.18.0.0/16 и отправляет **весь** свой трафик туда. В ядро
   попадают только помеченные MagiTrickle адреса; остальные ушли бы с
   роутера на поддельный адрес и не дошли бы никуда. То есть fake-ip
   принудительно возвращает «весь трафик через ядро» - ровно ту проблему,
   которую схема и решает. При redir-host клиент получает настоящий адрес,
   а ядро восстанавливает домен из TLS-handshake (sniffer включён).
3. **Списка рекламы в ядре нет.** В нём 110 000 доменов и около 20 МБ RAM
   ядра. MagiTrickle роняет его сам (`interface: blackhole`), так что ядро
   ни трафик не видит, ни список в памяти не держит. Цена - таймаут вместо
   мгновенного RST; в `RU-Mihomo-mixomo.yaml` написано, как вернуть быстрый
   ответ.
4. **`configVersion: "0.1.4"`.** Mod-сборка MagiTrickle принимает только
   `0.1.*`, оригинальная - всё, что начинается с `0.`. Значение должно
   работать с обеими.
5. **Поля, которые две сборки читают по-разному, не задаются.** `timeout` -
   длительность в оригинальной сборке (`5s`) и миллисекунды в mod-сборке
   (`5000`); `additionalTTL` - длительность в одной и секунды в другой.
   Значение, подходящее одной сборке, сломает другую, поэтому берётся дефолт
   сборки.
6. **Локальные группы собираются из rule-set'ов ядра.** Ядро умеет
   конвертировать свои `.mrs` обратно в текст (`mihomo convert-ruleset
   domain mrs <file> <out>`), поэтому Netflix, AI-сервисы, GitHub и Steam
   берутся из тех же списков, что и ядро, - один источник истины.
7. **Списки подписок - простые.** MagiTrickle разбирает по одному домену
   (или CIDR) в строке. Оказалось, что и список anti-AD простой
   (`anti-ad-domains.txt`, 110 923 строки), и списки Re-filter тоже - все
   они работают как подписка.

### Что проверено здесь

* `mihomo -t` на `RU-Mihomo-mixomo.yaml` настоящим ядром (v1.19.33).
* Ядро стартует с этим конфигом и слушает 7890, 5001, 7880 и 9090.
* `gen-mtrickle.sh` собирает состояние по rule-set'ам этого репозитория: 24
  домена у Streaming, 50 у AI, 66 у GitHub, 61 у Steam, подписки на месте, у
  каждого id - восемь hex-символов.
* Файл состояния и `.mtrickle` разбираются ruby и python и соответствуют
  схеме MagiTrickle (id, интерфейсы, флаги enable, url подписок).
* Три новых скрипта проходят `sh -n` и не содержат bash-синтаксиса.

### Что проверить здесь нельзя

Роутер с этой машины недоступен, поэтому остаются открытыми и должны быть
измерены на устройстве:

* RAM MagiTrickle с 200 000 правилами списков;
* действительно ли адреса помеченного трафика уходят с роутера через
  туннель (проверка `ip route show table 1298229097`);
* скорость и поведение UDP со схемой и без неё - ради этого всё и делалось.
