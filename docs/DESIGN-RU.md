# Заметки по дизайну

[English](DESIGN.md) | **Русский**

Каждое утверждение в этом файле измерено, а не взято из чужого README. Если
рядом с утверждением стоит число — вот как оно получено.

Замеры сделаны на **Cudy WR3000S v1** (MT7981BA, 2x Cortex-A53 1,3 ГГц,
256 МБ RAM, 128 МБ NAND, 5x1 GbE) с OpenWrt 25.12.5, прошивкой в разметке
`ubootmod` и OpenClash v0.48.002. Ядром был настоящий
`mihomo-linux-arm64 v1.19.33`, запущенный в эмуляторе того же SoC
(QEMU, машина `mt7981-router`), а не на ПК.

## 1. Роутер и его пределы

| | |
|---|---|
| RAM | 256 МБ, `zram` 168 МБ (сжатый swap, а не дополнительная память) |
| Флеш | 128 МБ NAND |
| Overlay (standard layout) | 44 МБ — **не хватает** |
| Overlay (ubootmod layout) | 84,8 МБ — нужна эта |

Бинарник `mihomo` для arm64 занимает 57,5 МБ на диске и 25–29 МБ в UBIFS.
Вместе с OpenClash (10,7 МБ), ruby и rule-set'ами (1,5 МБ) в стандартную
разметку он не влезает. Разметка `ubootmod` даёт ~50 МБ больше.

`zram` не даёт mihomo дополнительной памяти: 52 МБ ядра всё время живут в
резиденте. `zram` экономит только пики — ruby-переписывание при старте,
распакованное ядро в `/tmp` (а `/tmp` — это tmpfs, то есть RAM).

### Замеры RAM

| Конфигурация | RSS |
|---|---|
| голое ядро, без конфига | ~45 МБ |
| lite-конфиг, 154 ноды | **52,2 МБ** |
| полный конфиг (со списком рекламы) | 57,8 МБ |
| `GOMEMLIMIT=64MiB GOGC=50` | 53 МБ (реального выигрыша нет, это страховка) |

`MemTotal` в эмуляторе был 239 568 kB, `MemAvailable` после старта — около
100 МБ. Lite-вариант помещается с запасом.

## 2. Что OpenClash делает с конфигом

`yml_change.sh` — это 946 строк ruby. При каждом старте он переписывает:

* DNS (`enable`, `listen`, `enhanced-mode`, nameserver'ы)
* `fake-ip-filter`
* `hosts`
* `sniffer`
* `authentication` (из своей секции UCI)
* `external-controller` (`0.0.0.0:<cn_port>`) и `secret` (из
  `dashboard_password`)
* `allow-lan`, `bind-address`

Он **не** переписывает `proxy-groups`. Он только читает имена групп и
импортирует их в своё хранилище (`uci.rb`, `import_groups`).

Что он при этом переписывает молча:

* `config_cus_up` перезаписывает `filter` и `exclude-filter` каждого
  `proxy-provider` из фильтра нод в интерфейсе OpenClash. **Поэтому все
  фильтры в этом конфиге живут на группах и никогда на провайдере.**
* `yml_rules_change.sh` может перезаписать `tolerance`, `interval` и `url` у
  каждой группы `url-test` / `fallback` / `load-balance` / `smart` и сменить их
  `type` на `smart` (опция `AUTO_SMART_SWITCH`). В `RU-Mihomo.conf` стоит
  `AUTO_SMART_SWITCH = 0`.
* Если группы создаются в интерфейсе OpenClash, OpenClash **пересобирает весь
  блок `proxy-groups:`** (`uci.rb`, `write_groups`). Не создавайте группы в
  интерфейсе, пока используете этот конфиг.

### YAML-якоря

Якоря в этом конфиге — не догадка, они проверены на настоящем `YAML.rb`
из OpenClash:

* все ruby-скрипты OpenClash стартуют с `-ryaml -rYAML`, а `YAML.rb` OpenClash
  подменяет `load` на `unsafe_load`, поэтому алиасы и merge-ключи разрешаются
  при загрузке;
* дамп (`YAML.dump_string`) сохраняет якоря (`&1` / `*1`), и результат по-прежнему
  проходит `mihomo -t`;
* сам `mihomo` (yaml.v3) принимает алиасы на последовательности, алиасы на
  скаляры и merge-ключи.

Здесь используются только простые алиасы, без `<<:` merge-ключей, чтобы файл
оставался читаемым для инструментов, которые merge-ключи не умеют.

Одна оговорка: `Psych.load_file` *обычного* ruby (без `YAML.rb` OpenClash)
отвергает любой алиас — `Psych::AliasesNotEnabled`. Это важно только для ваших
собственных скриптов, не для OpenClash.

## 3. DNS

Схема:

* fake-ip, чтобы домен был известен до соединения;
* `respect-rules: true`, чтобы заблокированный домен резолвился через прокси,
  а российский — нет;
* основные резолверы — DoH **по IP** (`1.1.1.1`, `9.9.9.9`): чтобы разрешить
  хостнейм, нужен резолвер в первую очередь;
* прокси-серверы резолвятся напрямую (`77.88.8.8` — DNS Яндекса, из России
  отвечает надёжно), иначе подписка вообще не загрузится;
* российские домены резолвятся напрямую через DNS Яндекса, иначе ответ приходит
  из-за границы и вы получаете заглушку РКН.

### Находка про GeoSite

Очевидный способ отправить российские домены к российскому резолверу —
`nameserver-policy: "geosite:category-ru"`. Замерено на роутере:

| | RSS | Старт | GeoSite.dat |
|---|---|---|---|
| `geosite:category-ru` | **86,4 МБ** | 4598 мс | скачивается, 4,3 МБ |
| `rule-set:ru-domains` | **52,2 МБ** | 67 мс | вообще не скачивается |

`geosite:category-ru` заставляет ядро скачать `GeoSite.dat` и держать в RAM
весь geosite-матчер. `rule-set:ru-domains` указывает на локальный `.mrs`,
который и так уже на месте. Поведение идентично — проверено поломкой
policy-резолвера: российский домен после этого отдаёт SERVFAIL, а зарубежный
резолвится, в обоих вариантах.

`mihomo` поддерживает `rule-set:` в `nameserver-policy` (config/config.go).

### `fake-ip-filter`

Принимает только доменные rule-set'ы: IP-rule-set здесь заставляет ядро
отказываться стартовать.

## 4. Порядок правил

Порядок — не дело вкуса, он выведен из пересечений между списками:

1. `private`, `fake-ip-filter` -> DIRECT
2. `custom-domains` -> `⭐ Custom` — **ваше** решение важнее любого списка
3. `antiad` -> REJECT
4. сервисные группы -> **перед** списком РКН
5. `rkn-blocked`, `rkn-community`, `rkn-blocked-ips` -> `🚫 RKN Blocked`
6. `category-ai-ru` -> DIRECT
7. `ru-domains`, `ru-ips` -> DIRECT
8. `microsoft`, `apple` -> DIRECT
9. `cdn` -> `🌐 CDN`
10. QUIC -> REJECT
11. MATCH -> `🎯 Final`

Почему:

* **сервисы перед списком РКН.** Telegram, Discord и AI-сервисы есть и в
  списке РКН — измерено 13, 22 и 15 пересекающихся доменов. Если правило РКН
  окажется первым, выбрать нод для этих сервисов станет недостижимо, а для
  Telegram и Discord это критично: им нужен конкретный нод.
* **список РКН перед российскими доменами.** Есть домены вроде `007dom.ru`:
  российские по TLD, но в списке РКН. При `ru-domains` первым такой домен
  ушёл бы в DIRECT, то есть в обход блокировки.
* **`category-ai-ru` — это российский AI** (Алиса и подобные), а не OpenAI.
  Зарубежный exit IP для них неправильный. У зарубежных AI-сервисов есть свои
  списки (`openai`, `anthropic`, `google-gemini`, `xai`).
* **правило CDN после российских доменов**, чтобы хостнеймы CDN российских
  сервисов оставались напрямую.

### Ловушка «голых» доменов

Списки РКН приходят с голыми доменами (`instagram.com`). В mihomo голый домен
с `behavior: domain` совпадает **только с этим точным доменом** —
`www.instagram.com` проскакивает мимо. Замерено: с голым списком совпало 0
поддоменов из 12; с префиксом `+.` (DOMAIN-SUFFIX) — 12 из 12.

`scripts/build-ruleset.sh` добавляет префикс до конвертации, поэтому списки в
`ruleset/` корректны.

### `no-resolve` на правиле private

Rule-set `private` — это список IP (`behavior: ipcidr`). Чтобы сопоставить с
ним домен, ядру надо сначала этот домен разрешить. `no-resolve` эту
разрешку пропускает — и локальный хост по имени перестаёт попадать в
private-правило.

Замерено на mihomo v1.19.33 с fake-ip и локальным DNS-сервером, запрос к
`nas.test`, который резолвится в `192.168.1.10`:

| Правило | Что делает ядро |
|---|---|
| `RULE-SET,private,DIRECT` | `match RuleSet(private) using DIRECT` |
| `RULE-SET,private,DIRECT,no-resolve` | `match Match using PROXY` |

Во второй строке локальный хост уходит в прокси. Домены из
`fake-ip-filter` не затрагиваются (их IP известен заранее), но все остальные
локальные имена — затрагиваются. Поэтому опция выключена: её измерили и
отвергли, а не не заметили.

### `behavior: classical` вместе с `format: mrs`

Такое правило **молча не совпадает** — 0 доменов из 12 вместо 12 из 12.
Поэтому каждый rule-set в этом конфиге использует `behavior: domain` или
`behavior: ipcidr`.

## 5. Фильтры нод

Два регулярных выражения, оба на группах:

* `noise-filter` — LTE/4G-серверы и «info»-ноды подписки (счётчики трафика,
  срок действия, тарифы). Как прокси они непригодны никогда.
* `foreign-filter` — `noise-filter` плюс российские маркеры. Его используют
  автоматические группы, потому что **российский exit-IP ничего не
  разблокирует**: РКН блокирует трафик по российским сетям, и российский нод
  ломал бы ровно те сайты, ради которых этот конфиг и существует.

Старый конфиг выражал то же самое через lookahead (`^(?!.*(?:...)).*$`). Он
работает, но это backtracking-регулярка на каждом имени ноды, и читать её
трудно. `exclude-filter` ядро вычитает из `filter`, поэтому простая
альтернатива делает ту же работу.

Русские слова и российский флаг записаны escape-последовательностями `\x{...}`,
поэтому файл остаётся читаемым, а регулярки — ASCII:

```
\x{1F1F7}\x{1F1FA}  флаг
\x{041C}\x{043E}\x{0441}\x{043A}\x{0432}\x{0430}  "Москва"
```

**`\p{IsCyrillic}` использовать нельзя** — он роняет mihomo v1.19.33 паникой
в компиляторе регулярок. Движок — `dlclark/regexp2`, полная реализация PCRE,
так что lookahead'ы работают, если вдруг понадобятся.

`scripts/selftest.sh` проверяет, что шумовая часть `foreign-filter` всё ещё
совпадает с `noise-filter` — иначе LTE-нод мог бы попасть в автоматическую
группу.

### Проба (probe URL)

Каждая автоматическая группа меряет свои ноды по
`https://cp.cloudflare.com/generate_204`. Именно HTTPS, а не HTTP: проба идёт
через тот самый нод, который измеряется, и обычный HTTP-ответ может подделать
что угодно на пути. TLS-хендшейк — часть измерения, в этом весь смысл. URL
задан одним YAML-якорем (`&probe-url`), поэтому все группы и health-check
провайдера используют один и тот же.

### `find-process-mode`

`off`. На роутере трафик клиентов форвардится — искать локальный процесс
нечего, а правил `PROCESS-NAME` в конфиге нет. Поиск только тратил бы CPU.
(По умолчанию у mihomo `strict` — он ищет процесс для трафика, идущего от
самого устройства.)

## 6. Группы прокси

Зачем нужна каждая группа — в [GROUPS.md](GROUPS.md).

Группы `RU Nodes` больше нет. Её заменила `🎯 Manual`: в ней все ноды
подписки, включая российские, так что российский выход по-прежнему в один клик.

Три автоматические группы:

* `🚀 Auto` — url-test, tolerance 50 мс, 300 с
* `⚡ Turbo` — url-test, tolerance 0, 120 с: переключается быстрее и держится
  за самый быстрый нод даже при небольшой разнице
* `🔁 Failover` — fallback: держит первый ответивший нод и переходит дальше
  только когда тот умирает

## 7. Безопасность

Конфиг проверялся по коду OpenClash v0.48.002, поведение ядра измерялось.

| Настройка | Зачем |
|---|---|
| `secret: CHANGE_ME` -> `DASHBOARD_PASSWORD` | С пустым секретом API отвечает `Access-Control-Allow-Origin: *`: любая веб-страница в локалке может управлять прокси. OpenClash генерирует случайный пароль при установке, а `rmempty = true` в форме LuCI означает, что очистка поля **удаляет** опцию — поэтому пароль задаётся в `RU-Mihomo.conf`. |
| `external-controller-cors.allow-origins: []` | Ни одна страница из интернета не может говорить с API. |
| `external-controller-cors.allow-private-network: false` | Публичный сайт в локалке тоже не достучится до API (проверено preflight-запросом: заголовок исчезает). Сам дашборд same-origin и работает. |
| `authentication` | HTTP/SOCKS-порт требует логин и пароль. OpenClash заменяет блок своим случайным паролем. |
| `skip-auth-prefixes` | Только приватные сети, чтобы сам роутер мог пользоваться прокси. |
| нет `external-ui-url` | Ядро скачивает и распаковывает этот zip **без какой-либо проверки целостности** (проверено: принял zip по обычному HTTP с 127.0.0.1). Свой дашборд OpenClash всё равно ставит. |
| `geo-auto-update: false` | `GeoIP.dat` (16,5 МБ) и `GeoSite.dat` (4,4 МБ) этим конфигом не читаются. |

URL подписки не утекает через API: проверены `/configs`, `/providers/proxies`,
`/proxies`, `/connections` и `/rules` — токена нет ни в одном.

Порт дашборда с WAN недоступен: OpenClash отбивает `cn_port` на WAN-интерфейсе
в четырёх разных вариантах firewall. Диапазон CGNAT (100.64.0.0/10) эту цепочку
обошёл бы, поэтому не выставляйте роутер в интернет.

## 8. Smart-ядро

`type: smart` существует только в форке
[vernesong/mihomo](https://github.com/vernesong/mihomo). Апстрим MetaCubeX
отвечает `unsupported type: smart`, даже в v1.19.34.

`RU-Mihomo-smart.yaml` меняет тип `🚀 Auto` на `smart` и добавляет опции форка:

```yaml
policy-priority: "Premium:1.30;SG:1.15;\bRU\b:0.50"
uselightgbm: false
collectdata: false
sample-rate: 1
prefer-asn: true
```

* `policy-priority` — множитель для имён нод, которые подошли. `< 1` понижает
  приоритет, `> 1` повышает. Шаблон сначала пробуется как regex, а если не
  подошёл — как обычная подстрока; побеждает первое совпадение, несколько
  правил разделяются `;`.
* `uselightgbm` — использовать модель LightGBM для предсказания веса ноды.
  Нужен `Model.bin` — это **9,3 МБ**. На роутере с малым флешем держите его
  выключенным: smart-группа работает и без модели, она просто ранжирует ноды
  по своим замерам.
* `collectdata` / `sample-rate` — собирать данные для своей модели.
  `profile.smart-collector-size` ограничивает размер этого файла (по умолчанию
  100 МБ) — это ключ верхнего блока `profile`, в группе он игнорируется.
* `prefer-asn` — смотреть ASN при выборе нода. **Он заставляет ядро скачать
  `ASN.mmdb`, а это 8,7 МБ** (замерено: обычный конфиг его не качает, smart-конфиг
  с `prefer-asn: true` качает). Здесь он по умолчанию выключен: на роутере с
  84,8 МБ флеша это место дороже. Включайте, если есть где.
* `tolerance` — два нода, чьи задержки отличаются меньше чем на это значение,
  считаются равными, и дрожание задержки не переставляет список.

В smart-конфиге `⚡ Turbo` остаётся обычной url-test группой: всегда есть
запасной вариант, не зависящий от smart-ядра.

## 9. Известные ограничения

* `mihomo -t` не проверяет, существуют ли файлы rule-set'ов. Отсутствующий
  `.mrs` всплывает в логе во время работы, а не при валидации. Используйте
  `scripts/selftest.sh` — он проверяет файлы.
* `REJECT` в mihomo отвечает **HTTP 502**, а не 403. Это важно для любой
  проверки, которая смотрит на код ответа.
* Список РКН меняется каждый день. `scripts/build-ruleset.sh` рассчитан на
  запуск по расписанию — см. `.github/workflows/rulesets.yml`.
* Блок `x-fragments` не является частью mihomo. `mihomo` игнорирует неизвестные
  ключи верхнего уровня (проверено).
* Ядро скачивает `ASN.mmdb` (8,7 МБ), когда в группе есть `prefer-asn` или
  `type: smart` с включённым поиском по ASN. Обычный конфиг не качает его
  никогда, smart — тоже, пока `prefer-asn` остаётся `false`. Если флеша
  расходуется больше ожидаемого, посмотрите рабочий каталог ядра на роутере.

### Тестирование на эмуляторе WR3000S

Полный цикл проверен на настоящей QEMU-эмуляции платы, а не только на ПК.
Эмулятор — `github.com/stavultras/router-emulator` v4.1 с папкой прошивки
`nand-wr3000s`, ссылка есть в теме 4pda 1087457, пост #10376. Официальный
веб-эмулятор Cudy (`support.cudy.com/emulator/WR3000S`) — только симулятор
веб-интерфейса стоковой прошивки: OpenWrt и mihomo там не запустить.

Замеры в эмуляторе: OpenWrt 25.12.5 загружается, 256 МБ RAM, overlay 84,8 МБ,
ядро 6.12.94. `mihomo v1.19.33` работает со всеми 28 провайдерами (252 793
правила), RSS 37 МБ на пяти тестовых нодах. Запрос к `01-klinika-21.ru`
совпал с `RuleSet/rkn-blocked` — значит правка с дефисами работает от начала
до конца. `check-groups.sh` показал российскую ноду только в `🎯 Manual`, а
LTE/инфо-ноды — ни в одной группе. `update-rulesets.sh APPLY=reload`
пересобрал все 28 файлов прямо на роутере и перечитал конфиг живым ядром через
API без перезапуска.

Что эмулятор не воспроизводит: радио молчит (нет реального Wi-Fi), WAN — это
пользовательская сеть QEMU (нет настоящего провайдера и реальной блокировки
РКН), сам OpenClash не ставился — ядро запускалось напрямую с тем конфигом,
который создал бы OpenClash. Но это настоящая OpenWrt с целевыми объёмами
RAM и флеша, поэтому скрипты и ядро ведут себя так же, как на устройстве.
