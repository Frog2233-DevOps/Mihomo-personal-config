# RU-Mihomo

mihomo / OpenClash configuration for Russia.

Everything in this package is ASCII-only: no Cyrillic, no Chinese characters.
Group names, provider names and rule-set names are plain English, so nothing
depends on UTF-8 handling in the dashboard, in OpenClash's Ruby rewrite or in
the profile cache.

## Contents

| File | What it is |
|---|---|
| `RU-Mihomo.yaml` | The config. Full version, with ad blocking. |
| `RU-Mihomo-lite.yaml` | Same config without ad blocking (about 4 MB less RAM). Generated by `make-lite.sh`, do not edit by hand. |
| `RU-Mihomo.conf` | OpenClash overwrite config. Sets the options OpenClash would otherwise overwrite, and injects the subscription URL. |
| `build-ruleset.sh` | Builds and refreshes the `.mrs` rule files in `ruleset/`. |
| `make-lite.sh` | Regenerates `RU-Mihomo-lite.yaml` from `RU-Mihomo.yaml`. |
| `check-groups.sh` | Shows how the node pools came out, straight from the mihomo API. |
| `ruleset/` | 24 `.mrs` rule files, about 1.5 MB. |

## Install

1. Put `RU-Mihomo.yaml` on the router as `/etc/openclash/config/RU-Mihomo.yaml`
   and put the `ruleset/` folder at `/etc/openclash/rule_provider/`.
2. Put your subscription URL into `proxy-providers` -> `Main` -> `url`
   (the placeholder is `PASTE_SUBSCRIPTION_URL_HERE`), or let OpenClash inject
   it: `RU-Mihomo.conf` substitutes `$EN_KEY1` into that exact path.
3. Only one subscription is needed. There is no backup subscription.

If you use OpenClash, also load `RU-Mihomo.conf` as the overwrite config. It
matters, because OpenClash rewrites DNS, fake-ip-filter, hosts, sniffer,
authentication and proxy-groups in your YAML on every start. The `.conf` pins
the options that would otherwise be replaced with plugin defaults.

Before the first start: change `secret: CHANGE_ME` in the config. The
controller listens on `0.0.0.0:9090`, so with the default secret the API is
open to the whole LAN.

## Node groups

Nine groups, no country fan-out:

```
Proxy          main selector: Auto | Failover | RU Nodes | Foreign Nodes | DIRECT
Auto           url-test, fastest foreign server
Failover       fallback, switches when the current node stops answering
RU Nodes       Russian servers only
Foreign Nodes  every other server, manually selectable
Telegram       per-service node choice (+ RU Nodes)
Discord        per-service node choice
AI             per-service node choice (OpenAI, Anthropic, Gemini, Grok)
RKN Blocked    RKN-blocked domains: Proxy or REJECT
```

**Why Russian servers are not in the general pool.** RKN blocks traffic on
Russian networks. A Russian exit IP does not unblock anything, so a Russian
node in the auto-select pool would break exactly the sites this config exists
to open. `RU Nodes` is there for the opposite case: services that need a
Russian IP.

`Telegram` offers the RU pool, because Telegram only cares about the exit IP
and a Russian exit works fine for it. `Discord` and `AI` deliberately do not:
Discord connections from Russian IPs are restricted, and OpenAI and Anthropic
block Russian IPs outright.

**LTE servers and info-nodes are filtered out of every pool.** Subscription
info-nodes (traffic counters, expiry dates, plan names) are not servers at all,
and LTE servers are excluded per your request.

The filters are on the groups, not on the provider: OpenClash rewrites
provider-level `filter` / `exclude-filter` when a node filter is configured in
its UI, which would silently disable this logic.

### If your provider names servers differently

The node-name patterns are in the `proxy-groups` section of `RU-Mihomo.yaml`.
Three regexes, each used in several places:

- Russian servers: `(?i)(?:\x{1F1F7}\x{1F1FA}|\bRU\b|\bRussia\b|...)`
- Foreign servers: the same set, negated with a negative lookahead
- Excluded: `(?i)(?:\bLTE\b|\b4G\b|\bMobile\b|...)`

The Russian flag is written as `\x{1F1F7}\x{1F1FA}` (the regional indicator
pair R+U) and the Russian words as `\x{...}` escapes, so the file stays pure
ASCII while still matching Cyrillic node names.

Do NOT use `\p{IsCyrillic}`: it crashes mihomo v1.19.33 with a panic in the
regexp compiler.

After editing, check the result on the router:

```sh
./check-groups.sh                    # default: 127.0.0.1:9090
./check-groups.sh 127.0.0.1:9090 YOUR_SECRET
```

It needs `curl` and `jq` (`opkg install jq`).

## Rules and their order

The order is derived from measurements, not from taste:

1. `private`, `fake-ip-filter` -> DIRECT
2. ads -> REJECT (disabled in the lite variant)
3. service groups -> before the RKN list
4. RKN blocked -> `RKN Blocked` group
5. Russian AI services -> DIRECT
6. Russia -> DIRECT
7. Microsoft, Apple -> DIRECT
8. QUIC -> REJECT
9. everything else -> `Proxy`

Two details that are easy to get wrong:

**Service groups come before the RKN list.** Telegram, Discord and the AI
services are on the RKN list as well (measured: 13, 22 and 15 of their domains
overlap). With the RKN rule first, choosing a node for those services would be
unreachable, and for Telegram and Discord that is critical.

**The RKN block comes before the Russian domains.** There are domains like
`007dom.ru`: Russian by TLD, but on the RKN list. With `ru-domains` first,
such a domain would go DIRECT, i.e. straight around the block.

Russian AI services (`category-ai-ru`: Yandex Alice, rugpt.io and friends) go
DIRECT. They are Russian services, a foreign exit IP is wrong for them, and
they are not on the RKN list (measured: zero overlap).

## Memory footprint on a 256 MB router

Measured on a Cudy WR3000S v1 (MT7981BA, 256 MB RAM, 2x Cortex-A53) running
OpenWrt 25.12.5 with the `ubootmod` layout, using the Router Emulator
(`stavultras/router-emulator`, QEMU machine `mt7981-router`) with the real
`mihomo-linux-arm64` binary, 154 nodes in the provider, zram 168 MB.

| What | RSS | Free RAM left (of 234 MB) |
|---|---|---|
| mihomo alone, no rules | ~45 MB | - |
| `RU-Mihomo-lite.yaml` | **52 MB** | 100 MB |
| `RU-Mihomo-lite.yaml` + `GOMEMLIMIT=64MiB GOGC=50` | 53 MB | 100 MB |
| `RU-Mihomo.yaml` (with ad blocking) | 58 MB | 92 MB |
| `RU-Mihomo.yaml` + `GOMEMLIMIT=64MiB GOGC=50` | 50 MB | 98 MB |

Notes that matter more than the numbers:

- **Flash is the tighter constraint than RAM.** With the standard OpenWrt
  layout the overlay is only ~44 MB, and the mihomo arm64 binary alone takes
  ~25-29 MB there (UBIFS compresses it). The `ubootmod` layout gives an
  84.8 MB overlay (80 MB free), which is what the router should run.
- **zram does not give mihomo more memory.** It compresses pages that were
  evicted. mihomo needs its ~52 MB resident at all times; zram only absorbs
  the spikes (OpenClash's Ruby rewrite, a core update unpacking into `/tmp`,
  which is tmpfs and therefore RAM).
- **`GOMEMLIMIT` helps little here.** It saved 15-20 MB on a config that
  still pulled in GeoSite.dat, and nothing once the geosite matcher was gone.
  It is still worth setting as a safety net, but it is not a substitute for a
  lean config.
- **`/tmp` is RAM.** On OpenWrt it is tmpfs. Downloading a core or a provider
  into `/tmp` costs real memory.
- The core took 4.6 s to start with `geosite:category-ru` in the DNS policy
  and 67 ms without it.

## DNS

Blocked-in-Russia names resolve through the proxy route, Russian names resolve
directly. DoH over IP, not over hostname: resolving a hostname needs a
resolver in the first place.

`respect-rules: true` requires a non-empty `proxy-server-nameserver`,
otherwise the core refuses to start.

The Russian resolver is selected by a LOCAL rule-set
(`nameserver-policy: 'rule-set:ru-domains'`), not by `geosite:category-ru`.
The geosite variant makes the core download `GeoSite.dat` (4.3 MB) and keep
the whole geosite matcher in RAM: 86 MB instead of 52 MB. The behaviour is
identical - verified by pointing the policy resolver at a dead address: a
Russian domain then fails with SERVFAIL while a foreign one still resolves,
with either key. mihomo supports `rule-set:` in `nameserver-policy`.

## Updating the rule files

```sh
./build-ruleset.sh
```

Needs `mihomo` in PATH (for `convert-ruleset`) and network access.

Why the RKN lists are built locally instead of downloaded directly: they ship
bare domains (`instagram.com`), and in mihomo a bare domain matches ONLY that
exact domain, so `www.instagram.com` slips through. Measured. The script adds
the `+.` prefix (DOMAIN-SUFFIX) before converting to `.mrs`, and subdomains
match as well.

Can be put on cron.

## Measured facts about mihomo

Everything below was verified by running the core, not read from a README:

- `behavior: classical` + `format: mrs` does NOT match. The rule is silently
  skipped. Every rule-set here uses `behavior: domain` or `ipcidr`.
- A bare domain matches only the exact domain, not subdomains. This is why
  `build-ruleset.sh` rewrites the lists.
- REJECT through an HTTP proxy returns HTTP 502, not 403.
- `respect-rules: true` without a non-empty `proxy-server-nameserver` stops the
  core from starting.
- `rules` does not accept inline flow style (`[MATCH,DIRECT]`), only the block
  style.
- `exclude-filter` is subtracted from `filter`: a node matching both is
  dropped.
- `filter` and `exclude-filter` work on proxy-groups as well as on providers.
- `type: smart` exists only in the `vernesong/mihomo` fork. Upstream
  MetaCubeX does not have it, so the standard OpenClash core cannot run it.
- `global-client-fingerprint` was removed from mihomo; it only produces a
  warning.
- `nameserver-policy` accepts `rule-set:<name>` as a key, next to
  `geosite:<name>` (mihomo `config/config.go`). Using the local rule-set
  instead of `geosite:` avoids downloading `GeoSite.dat` and keeps the geosite
  matcher out of RAM: 86 MB -> 52 MB on the same router.

## Verified before shipping

- `mihomo -t` passes for both `RU-Mihomo.yaml` and `RU-Mihomo-lite.yaml`.
- Rule matching was probed end to end through the local proxy: 12/12 cases on
  both variants, including that a Russian AI service goes DIRECT and that a
  Russian TLD domain from the RKN list goes to the proxy, not DIRECT.
- The group layout was tested with 21 synthetic node names: Russian servers
  land only in `RU Nodes`, foreign servers only in `Foreign Nodes`, LTE and
  info-nodes in no group at all, and no server is lost: 32/32 checks.
- The same layout was re-checked on the real arm64 core inside the WR3000S
  emulator with 154 nodes: `RU Nodes` = 50 Russian, `Foreign Nodes` = 100
  foreign, `Auto` = 100 foreign only, `Telegram` = Proxy + RU Nodes +
  foreign, `Discord` and `AI` = foreign only, and zero LTE/info nodes
  anywhere.
- Memory was measured on that emulator, not estimated: 52 MB RSS for the lite
  variant, 58 MB for the full one, out of 234 MB of RAM.
- The package was audited: no non-ASCII characters, no CJK, no country groups,
  exactly one subscription, all rule references resolve.
